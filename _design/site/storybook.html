Splitwise UI kit · v1

One stylesheet, one script, every page

This page is the reference for every Splitwise screen. All components below are rendered live from the same two files the app uses, so what you see here is exactly what ships. Switch theme and accent in the top bar: every story updates.

  • assets/splitwise.cssTokens, themes, accents and every component class. Sections are numbered and commented.
  • assets/splitwise.jsThe Splitwise global: icons, appearance, toast, confirm, form validation, money, balance and avatar helpers.
  • assets/splitwise-app.jsThe SplitwiseApp global for app pages: data, money engine, sign-in guard and the shared top bar. See App pages.
  • <span data-icon="name">Icon placeholder, swapped for the SVG on load (or after Splitwise.hydrate(el)).
  • [data-close]Any button inside a <dialog> with this attribute closes it.

Foundations

Colour tokens

Always use the CSS variables, never a hex value. Light and dark values are chosen separately for at least 4.5:1 text contrast. The accent tokens change with the accent picker; --pos and --neg never do, because they carry meaning.

  • --bg / --surface / --surface-2Page ground, cards and dialogs, subtle fills.
  • --text / --muted / --subtlePrimary text, secondary text, tertiary labels. All pass AA on every surface.
  • --accent*Primary buttons, focus rings, selected states. --accent-fg is the text colour on an accent fill.
  • --accent-2*Orange highlight: brand mark, payment icons, .chip.hot. Use --accent-2 only as a fill with --accent-2-fg text; for orange text use --accent-2-ink.
  • --pos / --negMoney only, always together with a sign and a label.

Foundations

Motion

Motion only explains a change of state. Enter with --t-med + --ease-out, exit faster with --t-fast + --ease-in. Only animate transform and opacity. Everything is switched off under prefers-reduced-motion.

  • --t-fast 150msHover, exits, small state feedback.
  • --t-med 200msDialogs, toasts and menus entering.

Foundations

Icons

One outline family on a 24px grid with a 1.5 stroke. Icons sit next to text; an icon-only button must carry an aria-label.

Foundations

Layout primitives

Structure-only helpers in the od-layout layer: rows, stacks, grids and text overflow. Compose components from them instead of writing new flex rules. Data text (names, descriptions) may truncate; amounts and buttons never do.

Controls

Buttons

Use one .primary per screen for the main action (Add payment, Save). .secondary for alternatives, .ghost for low-emphasis actions, .danger for destructive ones, which always go through Splitwise.confirm.

  • .btn.primary|secondary|ghost|dangerVariants. 40px tall, 14px label.
  • .btn.sm / .btn.block36px compact / full-width 44px (login, sheets).
  • [aria-busy="true"]Loading: shows a spinner and blocks clicks. Click "Save expense" above.
  • .icon-btn44×44 icon-only button. Needs aria-label.
  • .link-btnInline text action inside forms.

Two transaction types, grouped under day headers, newest first. Payment: a member paid for the group, split equally (receipt icon, purple tag). Internal: one member paid another to reconcile (orange arrows, orange tag). The type is always written as text, never shown by colour alone.
